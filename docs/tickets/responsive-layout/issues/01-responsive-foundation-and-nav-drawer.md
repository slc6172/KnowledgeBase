# 01 — 響應式基礎建設與導覽抽屜

**What to build:** 手機瀏覽器開啟網站時，版面會依螢幕寬度自動切換；原本橫排在頂端的「新增文章／
分類管理／標籤管理」按鈕收進一個可以點擊展開的漢堡選單抽屜，抽屜裡能直接點回文章列表、新增文章、
分類管理、標籤管理，桌面版導覽列完全不受影響。

**Blocked by:** None — can start immediately

**Status:** done

- [x] 樣式模組建立 768px 斷點慣例（桌面 `>=768px` 維持現有置中欄寬版型；窄螢幕 `<768px` 套用新
      版型），後續票直接沿用同一慣例，不重新定義
- [x] 新增手刻行內 SVG 漢堡圖示，不引入外部圖示庫或字型、不新增任何網路請求依賴。
      實作時調整範圍：「更多」「篩選」兩個圖示延到各自真正的消費者（Ticket 02 的篩選面板、
      Ticket 03 的更多選單）出現時再加，這裡先只做本票用得到的漢堡圖示——本票只需要建立「手刻
      inline SVG」這個做法/慣例，不需要預先生出還沒有按鈕會用到的圖示（避免無人使用的推測性程式碼）
- [x] 窄螢幕下，頂端導覽列的「新增文章／分類管理／標籤管理」三個按鈕收進漢堡選單，不再橫向佔用
      版面寬度
- [x] 點擊漢堡圖示展開側邊抽屜，抽屜項目依序為「文章列表（新增項目）、新增文章、分類管理、標籤
      管理」，點擊項目觸發對應既有行為（導向文章列表、開啟新增文章編輯畫面、開啟分類管理、開啟
      標籤管理），各項目本身觸發的動作維持既有邏輯不變
- [x] 品牌文字（既有回首頁按鈕）在抽屜之外依然可點擊回首頁，行為不變
- [x] 桌面版型（`>=768px`）的導覽列版面與操作方式跟改動前完全一致
- [x] 新增靜態掃描測試（`test/NavDrawer.test.js`），驗證斷點慣例、抽屜／漢堡選單所需的關鍵 class
      或屬性存在於樣式與樣板原始碼中，防止未來被意外刪除或改壞
- [x] `docs/preview/` 底下的靜態預覽檔案同步更新這次的版面與抽屜互動，可在瀏覽器裝置模擬器直接
