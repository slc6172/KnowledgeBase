# 02 — 分類換父層級:分類管理頁「移動」操作

**What to build:** 分類管理頁的樹狀節點新增「移動」操作,可以把頂層分類移到
另一個頂層分類底下,或把子分類移回頂層。

**Blocked by:** 01 — 分類換父層級:moveCategory 函式

**Status:** ready-for-agent

**驗收方式:** 部署後手動操作、對照下列具體行為。

- [ ] 分類管理頁每個分類節點(頂層與子分類都要有)新增「移動」按鈕,點擊後
      展開一個選單:「設為頂層分類」+ 所有「目前是頂層且不是自己」的分類。
- [ ] 選定目標後呼叫 `moveCategory`,成功後重新載入整棵分類樹,新的父子關係
      正確反映在畫面上。
- [ ] 移動一個目前有子分類的分類時,選單裡不提供會直接違反 2 層限制的選項
      (介面上先過濾掉明顯不合法的選項,但後端的驗證仍然是最終防線,不能只靠
      前端過濾——用開發者工具繞過前端過濾直接呼叫時,後端錯誤訊息仍要能在
      畫面上清楚顯示)。
- [ ] 移動失敗時(例如後端回報「分類最多只能有 2 層」),畫面上有清楚可見的
      錯誤訊息,樹狀畫面不變成不一致的中間狀態。
- [ ] 移動後,文章編輯頁的分類下拉選單(`categories-tags`/`frontend`/03 既有
      功能)重新打開時能看到最新的父子關係(不要求即時同步,重新整理/重新
      進入看得到最新資料即可,跟 `frontend/06` 既有的驗收標準一致)。
