# 01 — 色彩 token 微調、標籤中性化與按鈕視覺層級

**What to build:** 整個應用程式(桌面與手機)的色彩比現在更淡一階、更低飽和度；標籤 chip 改成中性
灰階、不再靠顏色分辨；只有真正關鍵的少數動作（發布文章、新增文章、密碼保護確認、錯誤頁回列表）
維持深色實心填滿的按鈕，其餘操作性按鈕（搜尋、新增分類、分類/標籤節點列的行內重新命名與合併確認）
改用新的輕量強調樣式。狀態徽記（已發布/草稿）、危險操作（刪除）的顏色不變。

**Blocked by:** None — can start immediately

**Status:** done

- [x] 調整既有色彩 token 數值（`--color-primary`、`--color-ink-muted`、`--color-border`、
      `--color-accent` 等），整體更淡一階；`--color-bg` 維持不變
- [x] 新增 `--color-on-primary`／`--color-on-accent`／`--color-on-danger` 語意化 token（疊在
      色塊背景上的文字顏色），修掉樣式表裡唯一一處寫死的 `#FFFFFF`
- [x] `.tag`（全站共用的標籤樣式，文章卡片／詳情頁／標籤輸入框都共用同一條規則）改成中性灰階
      配色，不再使用點綴色
- [x] 新增一個「輕量強調」按鈕樣式類別（`.btn-tinted`：淺色底、深色文字/邊框，不是實心填滿）
- [x] 下列按鈕從 `.btn-primary` 改用新增的輕量強調樣式：文章列表的搜尋按鈕、分類管理的新增
      分類按鈕、分類節點列的行內重新命名／合併確認按鈕、標籤節點列的行內重新命名／合併確認按鈕
- [x] 下列按鈕維持 `.btn-primary` 實心填滿不變：發布文章、新增文章（topbar 全域主要 CTA）、
      密碼保護確認、找不到文章錯誤頁的回列表按鈕
- [x] 狀態徽記（`.seal`／`.seal--published`／`.seal--draft`）的顏色規則不變
- [x] 危險操作（`.btn-danger`、刪除相關按鈕）的顏色規則不變
- [x] 導覽抽屜、篩選面板、更多選單這些浮動面板的陰影維持不變，不套用「拿掉陰影」的規則——查證
      後確認文章卡片本身已經是無陰影的細邊框樣式，這次完全沒有陰影相關的改動
- [x] 圓角、字體（中文襯線標題字用法）、深色模式皆不變動
- [x] 桌面版型（`>=768px`）與窄螢幕版型（`<768px`）都套用同一份色彩／按鈕規則，不會有一邊調過
      一邊沒調的情況（token/class 是全站共用，兩種版型自動一致）

- [x] 樣式表裡沒有新增寫死的 hex 值繞過 token（測試裡額外驗證每個 hex 值只在 `:root` 出現一次）
