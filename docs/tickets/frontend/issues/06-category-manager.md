# 06 — 分類管理頁

**What to build:** 分類管理視圖——樹狀顯示既有分類(頂層分類 + 底下的子分類)、
建立(頂層或子分類)、改名、刪除,分別對應 `listCategories`/`createCategory`/
`updateCategory`/`deleteCategory`。

**Blocked by:** 01 — Web App 骨架 + 視覺設計系統、categories-tags/01 —
分類/標籤查詢函式

**Status:** done

**驗收方式:** 部署後手動操作、對照下列具體行為。

- [x] 進入分類管理視圖時呼叫 `listCategories()`,依 `parent_id` 把資料組成
      樹狀顯示:頂層分類(`parent_id` 為 null)各自列出,底下用縮排或巢狀清單
      顯示其子分類。
- [x] 分類清單為空時顯示明確的「還沒有分類」提示。
- [x] 有「新增頂層分類」的輸入/按鈕,呼叫 `createCategory(name, null)`,成功後
      畫面即時更新(不用整頁重新整理)。
- [x] 每個頂層分類旁邊有「新增子分類」的入口,呼叫
      `createCategory(name, parentId)`(`parentId` 是該頂層分類的 id)。
- [x] 子分類**不**顯示「新增子分類」入口(介面上就不讓使用者嘗試建立第 3
      層,而不是等後端報錯才知道不行)。
- [x] 對一個子分類呼叫 `createCategory` 若仍然發生(例如透過非預期路徑),
      後端丟出的「分類最多只能有 2 層」錯誤要能在畫面上清楚顯示,不是被吞掉。
- [x] 每筆分類有「改名」控制項,呼叫 `updateCategory(categoryId, name)`,
      成功後畫面即時反映新名稱。
- [x] 每筆分類有「刪除」控制項,呼叫 `deleteCategory(categoryId)`,成功後該筆
      (以及畫面上顯示的、若是頂層分類則其子分類會跟著)從樹狀清單移除,反映
      `schema.sql` 的 `on delete set null` 行為(子分類刪除父層後變成新的頂層
      分類,不是被一併刪除——畫面上刪除父層後,原本的子分類應該還留著、只是
      不再縮排在該父層底下)。
- [x] 任一動作(新增/改名/刪除)失敗時,畫面上有清楚可見的錯誤訊息。
- [x] 文章編輯頁(ticket 03)的分類下拉選單使用的是同一份 `listCategories`
      資料結構,本票新增/改名/刪除分類後,重新打開編輯頁的分類下拉應該要能
      看到最新狀態(不要求即時同步兩個畫面,重新整理/重新進入編輯頁看得到
      最新資料即可)。
