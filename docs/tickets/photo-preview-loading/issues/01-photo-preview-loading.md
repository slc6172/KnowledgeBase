# 01 — 圖片附件預覽載入體驗

**What to build:** 修正圖片附件預覽時,下載期間畫面完全空白的問題——改成持續
顯示載入中狀態直到圖片真正顯示出來,失敗時顯示明確錯誤。原圖上傳/儲存完全
不動,不產生任何縮小版的實體檔案。

**Blocked by:** None — 純前端改動,基於既有的 `attachment-preview` 功能
(`frontend/05`)。

**Status:** ready-for-agent

**驗收方式:** 部署後手動操作、對照下列具體行為。

- [ ] 點擊圖片附件的「預覽」後,在圖片實際顯示出來之前,畫面持續顯示「載入
      中」提示,不會出現一段空白的預覽框。
- [ ] 圖片載入失敗時(可用瀏覽器開發者工具模擬離線/阻擋圖片請求測試),畫面
      顯示清楚的錯誤文字,不會卡在「載入中」不動。
- [x] `<img>` 元素加上 `decoding="async"` 屬性。~~`loading="lazy"`~~——手動驗收時發現這個屬性會讓圖片卡死在「載入中」(它靠 IntersectionObserver 判斷元素是否進入畫面,但這個 `<img>` 故意留在 DOM 外面直到 `load` 才插入,永遠沒有機會被判斷、永遠不會觸發下載),已經移除,詳見 `src/JavaScript.html` 裡 `loadSignedPreview` 的註解。
- [ ] 預覽框加上 `max-height` 限制(搭配既有的寬度限制),長寬比極端的照片
      (例如很長的截圖)不會把整個詳情/編輯頁面往下推得過遠。
- [ ] 收合再重新展開同一個附件的預覽時(既有的 `data-loaded` 記憶機制),不會
      重複觸發下載或重新顯示「載入中」——這個既有行為不能被這次改動破壞。
- [ ] 附件的原始檔案上傳流程(`uploadAttachmentFile`)、`getSignedAttachmentUrl`
      連到的仍然是原圖,完全沒有修改。
